# review-gate — 観点別レビューの進行役(ユーザー版)

レビュアーを何体置いても、**人間が読むのは1枚**でなければ意味がない。
このスキルは招集と集約だけを行う。**自分の意見は足さない。**

## 0. プロジェクト版があればそちらに従う

同名のスキルはユーザー版がプロジェクト版を隠す(Claude Code の仕様)。
リポジトリに `.claude/skills/review-gate/SKILL.md` があるなら、**それを Read して、その手順に従う**。
以下はプロジェクト版が無いときの手順。

## なぜ skill であって agent ではないか

サブエージェントはサブエージェントを呼べない。招集はメインセッション側の役目なので、進行役は skill にする。

## 2つのゲート

| 起動 | いつ | 招集するレビュアー |
| --- | --- | --- |
| `/review-gate issue <N>` | issue に着手する前 | `pm-critic`, `customer-advocate` |
| `/review-gate pr` | PR を出す前 / 出した直後 | `sre-reviewer`, `security-reviewer`, `qa-reviewer`, `ux-designer` |

レビュアーは `~/.claude/agents/` のユーザー版。リポジトリの `.claude/agents/` に同名のものがあれば、
そちらが使われる(プロジェクト版が優先される仕様)。

引数が無い場合は、基準ブランチとの差分か未コミットの変更があれば `pr`、なければ `issue` と判断し、
**どちらで動くかを最初に1行で宣言してから**進む。

## 手順

### 1. 対象を確定する

- `issue` ゲート: `gh issue view <N> --comments`
- `pr` ゲート: 基準ブランチを決めてから差分を取る
  - PR があれば `gh pr view --json baseRefName,number` の `baseRefName`。差分は `gh pr diff`
  - 無ければ `CLAUDE.md` に書かれた PR の向き先、それも無ければ `gh repo view --json defaultBranchRef`
  - `git fetch origin <base>` のうえで `git diff origin/<base>...HEAD`

対象が空なら、レビュアーを呼ばずに `対象なし。` と返して終わる。

### 2. レビュアーを並列で招集する

**必ず1つのメッセージで全員を同時に呼ぶ。** 順番に呼ぶと待ち時間が人数分積まれる。

各レビュアーには次だけを渡す。
- リポジトリのパス、ゲートの種類
- 対象の識別子(issue 番号 / PR 番号 / ブランチ名と基準ブランチ)

**こちらの見解や、他のレビュアーの結果を渡してはいけない。** 独立していることが価値で、
先に出た意見を渡すと後続がそれに引きずられる。

### 3. 決裁書に畳む

各レビュアーの出力をそのまま並べない。次の1枚にまとめる。

```markdown
## 決裁書 / <対象>

| 観点 | 結論 |
| --- | --- |
| SRE | 条件付き |
| セキュリティ | 指摘なし |
| QA | 停止 |
| デザイン | 対象外 |

**停止させる指摘(これが1件でもあれば進めない)**
- `[SRE]` 内容 — 起きること — 提案

**要対応**
- `[QA]` 内容 — 起きること — 提案

**判断が要る論点**
- `[PM]` 内容 — 両論を1行ずつ

**推奨:** 進める / 修正して再実行 / 保留 / 却下 — 理由を1文で
```

畳むときの規則:

- **`[停止]` は一字一句そのまま運ぶ。** 要約して弱めない
- 複数のレビュアーが同じことを別の言葉で指摘していたら、**1件にまとめて観点を併記する**(`[SRE][QA]`)
- `指摘なし。` `対象外。` は表に載せるだけ。本文に書き起こさない
- **進行役は自分の指摘を足さない。** 気づいたことがあれば決裁書の外に「進行役より」として1行で書く

### 4. 結論を出す

| 状態 | 推奨 |
| --- | --- |
| `[停止]` が1件以上 | **修正して再実行**。ゲートは通っていない |
| `[要対応]` のみ | 進めてよい。未対応分は PR 本文に理由付きで残す |
| 全員 `指摘なし。` / `対象外。` | **進める** |

決めるのは人間。このスキルは推奨を出すだけで、ラベル変更・issue のクローズ・
PR の作成やマージ・PR へのコメントを行わない。

## やらないこと

- レビュアーの指摘を採否判断しない(弱める・省くをしない)
- レビュアーに他のレビュアーの結果を見せない
- 自分でコードを読んで指摘を追加しない
- 同じゲートを、指摘を無視したまま2回通さない

## 全員が黙ったとき

`指摘なし。` と `対象外。` だけが並ぶのは**正常**。決裁書を1行(`全観点 指摘なし。進める。`)に畳んで終える。
何かを絞り出させるために追加の質問を投げてはいけない。
