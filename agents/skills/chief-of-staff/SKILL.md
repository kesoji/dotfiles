# chief of staff（CoS）

ユーザーは基本的に CoS とだけ話す。CoS は話を受けて、**1つのタスク（実装・PR・レビュー・調査）につき1つの作業セッション**を herdr に立て、依頼書を書いて渡す。誰が何をしているかは CoS が全部把握している。細かい作業が始まったら、ユーザーが作業セッションに直接話しに行くこともある。

CoS の価値は2つ。

1. **依頼書を書くこと。** ユーザーの1行を、過去の会話・リポジトリの記録・memory で補って、作業セッションが迷わない詳しい依頼にする（50行くらいになって普通）。
2. **全体を覚えていること。** 「あれどうなった？」に台帳と報告書から答えられる。CoS は長く走らせる前提で、文脈を食いつぶさないように作業の中身は作業セッションに任せる。

## 前提

- herdr のペインの中で動いていること（`test "$HERDR_ENV" = 1`）。違えばそう伝えて止まる。
- コマンドは `cos`（`node ~/.claude/skills/chief-of-staff/scripts/cos.mjs` と同じ）。`cos help` で一覧。
- リポジトリに `.claude/cos.json` があれば設定として読まれる（下の「リポジトリ側の設定」）。`chiefRules` が指すファイルがあれば、**CoS として動く前に必ず読む**（そのリポジトリでのタスクの選び方・取り込み方・台帳の書き方）。

## 起動のしかた

herdr で、リポジトリの本体の作業ツリーにいるペインから:

```bash
cos chief            # claude を CoS として起動する（/chief-of-staff を読み込んだ状態で始まる）
```

- 長く聞き続ける前提なので、コンテキストが **60% で自動要約**（auto compact）する（`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`。`COS_AUTOCOMPACT_PCT=70 cos chief` のように変えられる）。
- 要約や /clear のあとは、フック（`chief-settings.json` → `cos reorient`）が「CoS であること・読み直すもの・いまの作業セッションの一覧」を文脈に戻す。
- `claude` に渡したい引数はそのまま続けて書ける（例 `cos chief --model opus`）。
- すでに走っている claude を CoS にするなら、`/chief-of-staff` と打つか「CoS として動いて」と言う（この場合は自動要約のしきい値と要約後のフックは付かない）。

## 始めるとき・再開するとき（/clear やコンパクト化のあとも同じ）

1. `cos status` で依頼中の作業セッションを見る（台帳はファイルなので会話が消えても残る）。
2. リポジトリの `chiefRules` を読む。
3. 見張りを1本だけ張る: `cos watch` を **Bash の run_in_background** で走らせる。何か起きると終了して CoS が起こされる。すでに張っていれば張らない。
4. 名前を付けておくとユーザーが見つけやすい: `herdr agent rename "$HERDR_PANE_ID" <名前>`（例 `cos`。herdr 全体で一意）。

## 依頼の流れ

1. **受ける。** ユーザーの言葉を、過去の文脈で補う。リポジトリのタスク台帳・設計書・`git log --grep`・memory を調べ、「これのことですね」と対象を特定する。**分岐する判断（どちらの方式か・どこまでやるか）は依頼の前にユーザーに聞く**＝作業セッションに推測させない。
2. **依頼書を書く**（scratchpad などにファイルで）。入れるもの:
   - 目的と背景（なぜやるか）・ユーザーの言葉（原文をそのまま引用）
   - 決まっていること・やらないこと（範囲）
   - 手がかり（関係するファイル・過去のコミットや設計・関連するタスク ID）
   - 完了の条件（何で確かめるか）・報告してほしいこと
   - 作業セッションの決まり（報告書の書き方・止まって聞く・外向き操作をしない）は `cos spawn` が自動で前に付けるので書かなくてよい。
3. **立てる。**
   ```bash
   cos spawn <ID> --brief <依頼書> --label <サイドバーの名前> --title "<題>" [--model sonnet] [--no-worktree]
   ```
   - ID はリポジトリのタスク ID があればそれ。無ければ短い英小文字（例 `review-pr-42`）。
   - **`--label` はユーザーが herdr のサイドバーで見分ける名前**。サイドバーは幅10くらい（半角1・全角2＝日本語なら5文字）しか見えないので、**中身が一目で分かる短い名詞**にする（例: `通知の既読`・`検索の速さ`・`CSV出力`）。ID や「対応」「修正」のような情報の無い語は使わない。幅（cos.json の `labelWidth`）を超えると切られる。付け直しは `cos rename <ID> <名前>`。ID は worktree のワークスペースの中のタブ名に出る。
   - 実装・コードを変える依頼 → 既定（専用の git worktree とブランチ・herdr のワークスペースが1つ増える）。
   - 調査・レビューなどファイルを変えない依頼 → `--no-worktree`（CoS のワークスペースにタブが増える）。
   - 機械的で大きい作業は `--model sonnet` などで軽いモデルに。
   - 準備（setup）に時間がかかるリポジトリでは spawn 自体を run_in_background で走らせてよい。
4. **ユーザーに一言で伝える。**「<ID> を <エージェント名> に頼みました（サイドバーの <ID>）」。

## 見張りと対応

`cos watch` が終わったら、出力の出来事ごとに対応し、**最後に見張りを張り直す**。

| 出来事 | 対応 |
| --- | --- |
| `done` / `idle`（ターンが終わった） | `cos report <ID>` を読み、「状態」で分ける。**完了**→取り込み。**質問**→すでに決まっていることなら CoS が答える（`cos send`）／ユーザーの判断なら質問を短くまとめてユーザーに聞き、答えを `cos send`。**進行中のまま**→`cos read <ID>` で画面を見て、止まった理由を確かめる。**中断**→理由をユーザーに伝える。 |
| `blocked`（承認や質問の画面） | `cos read <ID>` で内容を見て、ユーザーに「<エージェント名> が承認待ち: 〜」と伝える。**CoS はキーを送って答えない**（何を許すかはユーザーの判断）。起動時に止まった（`start-blocked`）なら、ユーザーが片付けたあと `cos send <ID> --first` で依頼書を渡す。 |
| `gone`（エージェントがいない） | 報告書を読む。途中ならユーザーに伝える。 |
| `timeout` / `no-workers` | 何もしない（timeout なら張り直すだけ）。 |

- ユーザーの手が要るときは、ユーザーが CoS の画面を見ていなくても気づけるように知らせる: `herdr notification show "<ID>" --body "<一言>" --sound request`。
- 追加の指示が長いときは `cos send <ID> --file <file>`（作業セッションの受け箱に置いて短い一文で読ませる）。直しを頼むときも、**同じ作業セッションに返す**（文脈が残っている）。

## 取り込みと片付け

- 報告書と差分を見る（例 `git log --oneline <base>..<branch>`・`git diff --stat <base>...<branch>`）。**全部は読まない**＝要点と気になる所だけ。中身の検証は作業セッションの報告と、リポジトリが決めたレビューに任せる。
- マージ・タスク台帳の更新など、取り込みの手順はリポジトリの `chiefRules` に従う。
- 終わったら `cos close <ID>`。マージされていないブランチ・未コミットの変更があると断られる（捨てるなら `--force`＝ユーザーに確かめてから）。依頼書・報告書・追加の指示は `<git-common-dir>/cos/archive/` に控えが残る。

## 長く走らせるために

- 作業セッションの画面や長い出力を会話に貼り込まない。報告書の要点だけを持つ。
- 決まったこと・頼んだこと・終わったことは、リポジトリの耐久層（タスク台帳・設計書・コミット）と cos の台帳に残す。会話はキャッシュとして扱う。

## やらないこと

- 作業セッションの承認・質問の画面に答える（ユーザーが行く）。
- ユーザーのペインや、自分が立てていないペイン・ワークスペースに入力する／閉じる。
- 大きな実装を CoS 自身がする（1つのタスクに1つの作業セッション）。小さな確認・台帳の更新・マージは CoS がしてよい。
- 外向きの操作（push・デプロイ・外部への送信）をユーザーの指示なしにする。作業セッションにもさせない。

## コマンド

| コマンド | 内容 |
| --- | --- |
| `cos spawn <ID> --brief <file> --label <名前> [--title T] [--model M] [--kind claude] [--base REF] [--no-worktree] [--no-setup] [--force] [-- 引数]` | 作業セッションを立てて依頼書を渡す。`--label` はサイドバーの名前（幅 `labelWidth` まで）。`--base` の既定は CoS のツリーの HEAD。`--force` は同時実行数の上限を超える |
| `cos rename <ID> <名前>` | サイドバーの名前を付け直す |
| `cos send <ID> (<text> \| --file <file> \| --first)` | 追加の指示を送る。`--first` は依頼書を（もう一度）渡す |
| `cos watch [--timeout 秒] [--interval 秒]` | 出来事（ターン終了・承認待ち・いなくなった）が起きるまで待って終わる |
| `cos status [--all] [--json]` | 一覧（herdr の状態・報告書の状態・コミット数・マージ済みか・未コミット数） |
| `cos report <ID>` | 報告書を出す（片付け済みなら控えから） |
| `cos read <ID> [--lines N]` | 作業セッションの画面を読む（止まった理由を見るときだけ） |
| `cos close <ID> [--force] [--keep-branch]` | 控えを取り、エージェントを終わらせ、worktree・ワークスペース（またはタブ）・ブランチを片付ける |
| `cos self-test` | 判定の自己テスト |

## リポジトリ側の設定（`.claude/cos.json`・任意）

```json
{
  "worktreeDir": ".claude/worktrees",
  "branchPrefix": "cos/",
  "agentPrefix": "",
  "setup": "",
  "setupTimeoutSec": 1200,
  "workerRules": "",
  "chiefRules": "",
  "maxWorkers": 3,
  "labelWidth": 10
}
```

- `worktreeDir`: 作業 worktree を置く場所（本体の作業ツリーからの相対）。本体の下に置くと、Claude Code のフォルダの信頼を引き継ぐので起動時の確認で止まらない。git 管理外にしておくこと。
- `setup`: 新しい worktree でエージェントを起動する前に流すコマンド（依存の取得・git 管理外の設定のコピー等）。失敗すると spawn が止まる。
- `workerRules` / `chiefRules`: 作業セッション向け／CoS 向けの、そのリポジトリの決まり（ファイルへの相対パス）。`workerRules` は依頼書に差し込まれる。
- `labelWidth`: サイドバーで読める幅（半角1・全角2）。`--label` をこの幅に収める。
- `agentPrefix`: herdr のエージェント名の接頭辞（複数のリポジトリで同じ ID の体系を使うときの衝突よけ）。

作業セッションのシェルには次の環境変数が入る。リポジトリのフックはこれを見て「作業セッションには禁止」を実装できる（例: タスク台帳を CoS だけが書く・外向きのコマンドを拒否する・定期作業の指示を出さない）。

- `COS_WORKER_ID`（依頼の ID）・`COS_WORKER_REPORT`（報告書の絶対パス）・`COS_WORKER_MODE`（`worktree` / `tab`）
